# 多源调研决策机制（multi-agent consultation）

> 把"网络调研"从单一通道升级为**多源群策群力**：对重点决策/自身能力不足的问题，通过外部 Chrome 依次问多家 AI（免费优先，开通付费则用付费），差异化提问 + 交叉验证 + 可执行结论。
> 首版沉淀于 2026-10-06（珠宝搜索方法论问题 5 家群策群力实践：Gemini/ChatGPT/Claude/Grok/DeepSeek 高度一致、零冲突，增量全量吸收进《搜索方法论 v2》）。

## 一、分层路由：所有调研需求都走本技能（按层选择力度）

| 层 | 适用 | 耗时 | 动作 |
|---|---|---|---|
| **L1 轻量速查** | 事实核查、快速概念、单一事实问题、翻译/改写核对 | ≤10min | 内置搜索或 web.fetch 精读，必要时问 1 家 AI 交叉；**不启动多源** |
| **L2 标准调研** | 一般调研、选型对比、行业了解、资料搜集汇总 | 30-60min | 搜索引擎 + 2-3 家高互补 AI + 关键事实交叉核验（web-research-toolkit 标准 7 步流程） |
| **L3 深度决策** | **重点决策、自身能力不足/不确定的问题**、高风险结论、跨领域综合 | 1-2h | 完整多源机制（下文第二~七节全部）+ 三角验证 + 情报卡片 + 固定结论格式 |

**判定**：问题影响方向/方案/投资/合规 → L3；拿不准 → 按 L2 起步，发现证据冲突或信息不足再升级 L3。**用户点名"群策群力/多 AI 交叉验证"时直接 L3**。

## 二、渠道矩阵（P0-P4，覆盖国内外主流）

| 阶段 | 优先级 | 渠道（代表） | 类型 | 使用时机 | 付费建议 |
|---|---|---|---|---|---|
| 快速摸底 | P0 | Google / Bing / 百度（+搜狗/夸克/DuckDuckGo/Startpage/Brave/Yandex/Kagi） | 传统搜索引擎 | 永远先做 | 免费优先 |
| 通用推理 | P1 | Grok / Claude / ChatGPT / Gemini（+Perplexity/Copilot/Meta AI/Mistral/Poe/You.com/Cici） | 国外通用大模型 | 同步或紧接搜索后 | 有付费就用最新模型 |
| 中文/垂直 | P2 | DeepSeek / 豆包 / 元宝（+文心/通义/智谱/Kimi/讯飞/海螺/天工/阶跃/百川/零一/360/澜舟） | 中文优化模型 | 中文语境/国内政策/本地化时 | 免费优先 |
| 专业数据 | P3 | Perplexity / Consensus / Elicit / You.com（+ChatGPT Search/Gemini AI Mode/秘塔/天工AI搜索/纳米/Kimi Search/Phind/NotebookLM/Google AI Overviews） | 带引用 AI 搜索/学术引擎 | 需要证据链/论文/数据时 | 有付费用付费 |
| 补充 | P4 | 自定义技能（本工具链）/ 垂直领域引擎 / 小众工具 | 自建或垂直 | 前序结果不足时 | 按需 |

> **完整清单**（每类全部渠道 + 厂商/免费付费/API/网页/登录/需代理/停服坑）见 **`channel-directory.md`**（2026-10 版，多源验证）。矩阵只放代表渠道与组合策略。

**选择策略（怎么按问题选渠道，详见 channel-directory.md §八）**：中文语境→国内组+百度/秘塔；要引用→Perplexity/ChatGPT Search/Consensus；实时社媒→Grok/站内；长文档→Kimi/Claude/NotebookLM；学术→Scholar/arXiv/Patents；开发排错→Phind/ChatGPT/Claude/GitHub；免费优先→豆包/DeepSeek/Kimi/秘塔/天工。

**默认启动组合**（L3）：Google（或 Bing）＋ Grok + Claude（或 ChatGPT）＋ DeepSeek 或豆包（中文场景）＋ Perplexity / Consensus（需要引用时）。
**不需要全部问完**——只有当前组合结论冲突或证据不足时再追加渠道。渠道/模型更替在 `channel-directory.md` 登记。

## 三、差异化提问原则（不是每个渠道问一样的）

- **搜索引擎**：找原始证据和最新动态（用《搜索方法论 v2》操作符/模板）
- **通用大模型**：逻辑推演、多角度分析、方案生成（第一轮统一框架，见模板 B）
- **中文模型**：补中国本地化视角（国内政策/数据/实践，标注时效）
- **专业引擎**：要引用和数据支撑（citations + confidence level）
- **绝不把同一段话原封不动复制到所有渠道**——按渠道优势差异化提问；若问题本身与渠道优势重叠，可省渠道

## 四、提问模板（复制即用）

**模板 A 搜索引擎**：
```
[核心问题] site:edu OR site:gov OR site:org OR "研究报告" OR "白皮书" OR "统计数据" -广告 -推广
中文补充：[核心问题] 最新 研究报告 OR 官方数据 OR 政策文件 filetype:pdf
```

**模板 B 通用大模型（第一轮统一框架）**：
```
问题：[完整描述问题]
背景：[简要背景 + 你已有的认知]
要求：
1. 给出 3 种可能的观点/方案，并标明支持证据强度（高/中/低）
2. 指出主要风险与不确定性
3. 给出可执行的下一步行动建议（按优先级排序）
4. 如果信息不足，明确告诉我还需要补充什么信息
请用结构化输出（标题+要点）。
```

**模板 B2 第二轮（针对冲突深化）**：
```
刚才你给出了观点X，但其他来源给出了观点Y。请对比两者的假设、数据来源和适用场景，并给出你更倾向哪一方以及理由。
```

**模板 C 中文优化模型**：
```
问题：[核心问题]
请从中国语境出发回答：
1. 国内最新政策、数据或实践是怎样的？
2. 与国际主流观点有何差异？
3. 给出适合中国用户的可落地建议。
请标注信息时效性。
```

**模板 D 专业数据引擎**：
```
[核心问题]
Focus on recent studies, meta-analyses, and official statistics.
Provide citations and confidence level.
```

## 五、标准执行流程（L3 照做，L2 裁剪）

1. **问题拆解**（5 分钟内）：把大问题拆成 2–4 个可验证子问题
2. **第一轮快速摸底**：搜索引擎（P0）+ 1–2 个通用模型（P1），模板 A+B
3. **冲突检测与差异化追问**：发现明显分歧 → 模板 B2 + 模板 C/D 针对性补充
4. **交叉验证与自我判断**：证据一致性？来源权威性？时效性？偏见？→ **主控者加权决策，不是简单投票**
5. **输出可执行结论**（固定格式）：
   ```
   【结论】一句话核心判断
   【依据】3–5 条关键证据（带来源）
   【风险】主要不确定性
   【行动】下一步具体做什么（含优先级）
   【信息缺口】如果还需要补充什么
   ```
6. **归档与迭代**：保存本次渠道组合、提问模板、结论 → 存入项目产出或监控仓 `ai-consultation/`；下次同类问题复用或微调

## 六、浏览器执行要点（外部 Chrome 实测，2026-10-06）

- 统一走**外部 Chrome**（`mac_computer_use_tool` plane="bu" / `seed_browser_use`），不用应用内浏览器；详见 `browser-use-automation-mac` 技能
- 各平台输入框多为自定义编辑器：**长中文 `bu.type` 会截断乱码** → 用剪贴板法：Bash `pbcopy` 写入完整文本 → 页面 click 输入框 → ⌘V 粘贴 → Enter 提交（已验证 Grok/DeepSeek）
- 登录墙（ChatGPT/Claude/Grok/DeepSeek 首次均需登录）：调 `interaction.request_action(browserControl)` 移交用户，返回后重新观察，不复用旧 refs
- 登录态实测：Gemini/ChatGPT/DeepSeek 会话长期有效；Claude 可能非自愿登出需重登；Grok 登录后会话可复用
- 读取长回答：轮询等待"正在生成/工作于"消失 → `get_page_text` 分段读尾 → `content_export` 读全文
- 每家回答**必须即时存档**（如 `artifacts/ai-consultation/<平台>.md`），格式："回答要点 + 与我们方法论的对比发现"

## 七、与本工具链其他技能的分工

- 网页取数/精读/信源分级 → web-research-toolkit 主流程（channel-selection.md / research-workflow.md / source-schema.md）
- 搜索操作符/关键词工程/信号筛选/查询模板 → 《搜索方法论 v2》（监控仓 `03_监控机制/搜索方法论.md`，本技能可引用其模板库）
- 视频/音频平台（抖音/B站/YouTube）素材 → `multiplatform-media-fetch`
- 行业特定词库/查询包 → `industry-packs.md`（第八节登记）

## 八、更新机制（自我迭代 + 用户更新开关）

**本机制不是一成不变，按以下开关更新：**

1. **版本管理**：本文件头部版本号 + 文末《变更记录》。每次实质修订：升版本号、追加变更记录行（日期/改动/原因）
2. **自我更新（自动触发）**：每次使用后复盘——哪些渠道贡献最大？哪些提问低效/失效？累积 3–5 次使用或发现明显失效（渠道打不开、模型下线、模板不再适用）→ **自动修订本文件**（渠道表/模板/执行要点），并在变更记录登记
3. **用户更新（手动开关）**：用户随时可要求"更新调研机制"，或指认某处失效 → 按用户指示修订；新渠道/新模型上线 → 登记进渠道矩阵
4. **行业包扩展**：新行业需求 → 在 `industry-packs.md` 建行业包（词库+查询模板+渠道补充），包与包独立、可复用
5. **自己调研也用本技能**：执行任何调研任务时，按第一节分层路由选择力度；L2/L3 必须走本机制并留下存档（可溯源、可复盘）
