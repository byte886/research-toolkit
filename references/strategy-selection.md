# 调研策略选择与组合用法（strategy-selection）

> 回答"这个调研用什么策略、怎么组合、用什么方式决定策略"。三篇配套：`research-router.md` 定"是哪类调研、哪层"；`channel-directory.md` 定"有哪些渠道"；本篇定"策略怎么选、怎么组合、怎么叠加升级"。机制主文档见 `multi-agent-consultation.md`。
> **完整调研策略 = 三维度组合**：①**选哪些渠道/AI**（channel-directory + 渠道矩阵）②**单步动作用什么组件**（S1-S10）③**AI 之间怎么协作**（第五节协作模式）。三维度可独立选、可重叠组合。

## 〇、选择三维度（先定维度再看细节）

| 维度 | 回答什么 | 依据 |
|---|---|---|
| 渠道（用谁） | 哪些搜索引擎/AI/专业库上场 | `channel-directory.md` + 渠道矩阵 P0-P4 |
| 组件（怎么做） | 单步动作用哪些策略积木 | 本节 S1-S10 |
| 协作模式（怎么配合） | 多个 AI 之间按什么结构协作 | 第五节

## 一、四种决策模式（怎么决定"用什么策略"）

| 模式 | 做法 | 适用 | 成本 |
|---|---|---|---|
| **① 规则路由（模板决策）** | 查 research-router 类型表 + channel-directory 选择策略，按规则直接选 | 高频/常规调研（80% 场景） | 最低 |
| **② 自省评估（半规则半判断）** | 快速评估四维：复杂度(1-5)×重要性(1-5)×时效性×领域 → 套策略档 | 拿不准类型/边界模糊 | 低 |
| **③ 群策元决策（AI 帮选策略）** | 把"该用什么调研策略"本身抛给多家 AI 征询，再按共识执行 | 重点决策/全新领域/首次接触 | 高（值得时才用） |
| **④ 预算门控（成本反推）** | 按可承受时间/token/付费反推力度：L1≤10min、L2≤1h、L3 再评估 | 预算/时间明确受限 | 低 |

**组合规则**：常规→①；模糊→②；重点→①+③；预算受限→④ 约束 ①/②。多类混合调研按 research-router 取最高层。

## 二、策略组件（S1-S10，可任意组合、可重叠）

> 组件之间不互斥，按需叠加。这是"组合用法"的最小积木。

| 组件 | 内容 | 典型用途 |
|---|---|---|
| **S1 双引擎对比** | Google+百度（或 Bing）同题搜索，对比结果差异 | 快速发现地域/语言/索引偏差 |
| **S2 三 AI 同问** | 同题问 3 家（如 Grok/Claude/DeepSeek），对比答案差异点 | 观点交叉、补视角 |
| **S3 冲突深化** | 两家结论不一致时，把**分歧点单独**问第三/第四家 | 消歧、找真相 |
| **S4 角色分工** | 显式分工：A 查事实、B 挑毛病、C 总结成稿 | 群策群力时防"同质化答案" |
| **S5 证据梯度** | 官方源 > 权威报告 > 评测/社区 > 自媒体，逐级下探 | 溯源与可信度管理 |
| **S6 平台双排序** | 同平台两种排序（综合/最新）交叉 + 信号词偏置 | 舆情/社媒挖掘 |
| **S7 垂直库+通用补** | 先垂直权威库（pkulaw/学术/医疗/公告），再通用搜索补外部视角 | 领域问题防"只见一面" |
| **S8 实操验证** | 文档/评测之外做小样本实测（跑脚本/试接口/开免费档） | 选型落地前证伪 |
| **S9 溯源三步** | 找首发 → 找原始数据 → 核对口径 | 一切数字核验 |
| **S10 异常词扫描** | launch/pilot/beta/partnership/上线/首发 等信号词扫动态 | 新品/政策/竞品动态监控 |

## 四、重叠、升级、回退规则

- **可重叠**：组件间不互斥，S1+S2+S7 可同时跑；渠道重叠本身就是交叉验证（同一问题多通道并行）。
- **可升级**：先跑基础档，证据冲突或信息不足 → 叠加增强档组件；L2 中发现重大分歧 → 升 L3 完整机制。
- **可回退**：增强档仍无结论 → 退回并记录"此路不通"（防止死循环与 token 空耗）；同一策略失败两次即换组合。

## 五、群策元决策模板（让 AI 帮选策略，L3 用）

把"用什么策略"当问题抛给多家 AI（按 multi-agent-consultation 差异化模板问）：

> "我要调研【主题/目标】，交付物是【报告/对比表/决策建议】，约束是【时间/预算/可用的账号与工具】，之前已知【已有线索/已排除的方向】。请给一套可落地的调研策略：①用什么渠道组合（哪些搜索引擎/AI/专业库）②先后顺序与时间分配 ③怎么交叉验证与防坑 ④哪些环节可能白费力气。请结构化、可直接执行。"

收到多家建议后：取交集为必做、取分歧点单独追问、按本技能分层与预算门控收敛成最终策略再执行。

## 五、协作模式策略（AI 之间怎么协作，2026-10 多源验证）

> 决定"多个 AI 怎么配合"：谁主导、谁认领、怎么流转、怎么裁决。模式之间可**混合嵌套**（如 主从+并行+共识 组合），不是互斥单选。

### 5.1 十种协作模式（调研场景视角）

| 模式 | 本质 | 调研场景适用 | 风险 |
|---|---|---|---|
| **并行扇出/汇聚**（Fan-out/Fan-in） | N 家 AI 同时干独立子任务，再合并 | 多源调研默认首选：3 家 AI 同题各查各的 → 汇总对比 | 合并步最易被低估（结果互不引用、口径不一） |
| **顺序流水线**（Pipeline） | A→B→C 接力，前输出是后输入 | 线性流程：搜 → 核 → 成稿；稳定易监控 | 不灵活，异常分支难处理 |
| **层级主从**（Orchestrator-Workers） | 一个主管拆任务、派发、汇总；专员不互聊 | 有明确主控（本 Agent 主导）、需审计留痕 | 主管是单点故障/瓶颈 |
| **黑板/画板式**（Blackboard / Shared Board） | 共享工作区，各协作者看到需求**自行认领**、有货就写上去 | 开放式探索；多角色认领（如珠宝情报：A 认领工具动态、B 认领案例、C 认领合规） | 可能无人认领冷门块；认领冲突 |
| **辩论/对抗**（Debate / Adversarial） | 两方对立论证，judge 裁决 | 决策评估、正反两说校验、事实分歧消解 | 为辩而辩、耗时 |
| **共识/集成**（Consensus / Ensemble） | 多家各自独立作答，投票/取交集 | 群策群力的本质：多 AI 交叉验证，取共识为结论 | 无共识时需升级冲突深化 |
| **角色分工**（Role Assignment） | 具名角色各司其职（researcher/writer/critic/planner） | 群策时显式分工：A 查事实、B 挑毛病、C 成稿（=S4） | 角色边界需事前说清 |
| **事件驱动 Pub-Sub** | 松耦合，事件发布订阅 | 持续监控类（渠道动态/新品上线事件流） | 调试难、终止条件弱 |
| **点对点**（Peer-to-Peer） | 无中心，agent 直接协商边界 | 平级多来源对等交换（少见，重依赖时用） | 全局观弱、易冲突 |
| **群体 Swarm** | 无中心，任务板自选+生命周期状态 | 高弹性探索（风险/成本高，调研慎用） | 终止条件难控制，可能空转 |

### 5.2 怎么选协作模式（需求特征 → 模式）

| 需求特征 | 协作模式 |
|---|---|
| 子问题互相独立、要多源对比 | **并行扇出 + 共识**（默认） |
| 流程线性依赖（搜→核→写） | **顺序流水线** |
| 决策拍板/正反校验 | **辩论** 或 **共识+冲突深化** |
| 开放式探索、多角色认领 | **黑板/画板式**（可叠角色分工） |
| 需主控留痕、清晰审计 | **层级主从** |
| 持续盯变化 | **事件驱动** |

### 5.3 组合与嵌套（可共存）

- **主从 + 并行**：本 Agent 主管拆 3 个子任务，并行派 3 家 AI → 各自回卷 → 主从汇总
- **并行 + 共识**：3 家同题 → 对比 → 共识项直接采信，分歧项进辩论/冲突深化
- **黑板 + 角色**：共享画板挂需求清单，researcher/critic/editor 各认领一块
- **画板 + 流水线**：画板收各协作方产出，再按固定顺序过质检节
- **切换规则**：一种模式跑不顺（认领空转/共识僵持/主管过载）→ 换模式或嵌套补一层，同一问题失败两次即切。

### 5.4 与群策群力的衔接

群策群力（multi-agent-consultation 的多 AI 提问）天然是 **并行扇出 + 共识**；需要更强结论时升级 **辩论/冲突深化**；本 Agent 汇总成稿时进入 **顺序流水线** 或 **层级主从**。协作模式不改变渠道选择，只改变"这些 AI 怎么被组织"。

## 六、强需求渠道指定（某渠道是强需求时直接指定，不走通用选择）

> 当某类调研对特定渠道**强依赖**时，直接指定该渠道为主渠道（第一优先级），其余按常规补视角。命中即指定，不需要再走决策模式①/②的通用选择。

### 6.1 判定标准（命中任一即强需求）

1. **信息只存在/最权威于该渠道**：法规（pkulaw）、医学（权威库）、学术（Scholar/PubMed）、公司数据（财报/公告）、政府统计（统计局/央行）
2. **平台站内私有内容**：抖音/小红书/微信站内数据、生财有术会员内容——通用搜索拿不到或严重滞后
3. **时效性只在该平台**：社媒实时（X/Grok）、电商销量（蝉妈妈/飞瓜）、监控对象自身发布渠道
4. **合规/一手要求**：政策/红头文件、官方公告、法规条文原文

### 6.2 强需求渠道清单（命中即指定为主渠道，可扩展）

| 调研需求特征 | 强需求渠道（指定为主） |
|---|---|
| 中国大陆法规/合规 | pkulaw-legal-data（北大法宝） |
| 医疗/用药/体检 | 医疗权威库/指南（doubao-medical-* 技能链） |
| 学术论文/文献 | Google Scholar / arXiv / PubMed / Consensus |
| 上市公司经营/公告 | 巨潮资讯 / 披露易 / 财报原文件 |
| 抖音内容/数据 | 抖音站内（multiplatform-media-fetch / 站内搜索） |
| 小红书内容/数据 | 小红书站内（xhs_downloader / 浏览器登录） |
| 微信/公众号 | 微信搜一搜 / 公众号站内 |
| 生财有术会员内容 | scys-mcp（站内私有，OAuth） |
| 实时社媒（X） | Grok / X 站内 |
| 电商销量/达人/热度 | 蝉妈妈 / 飞瓜 / 巨量算数 |
| 政府统计/宏观 | 统计局 / 央行 / 海关总署官方 |
| 招聘/人才趋势 | BOSS 直聘 / 猎聘 / 脉脉 |
| 开源项目/竞品方案 | GitHub（search/trending） |
| 政策/红头文件 | policy-source-map 指定权威库 |

### 6.3 处理规则

- **命中 → 指定为主渠道**（先跑、给足权重），其余渠道按常规路由补外部视角；把"建议以【渠道】为主（理由）"写进调研方案，让执行者与用户都可见
- **未命中 → 常规选择**（决策模式①规则路由 / ②自省评估）
- **强需求渠道不可用时**：如实报告"该渠道不可用"及信息损失，不静默用通用搜索替代假装覆盖（如抖音站内被限 → 报告缺口）
- **清单扩展**：新增强需求组合先在 `channel-directory.md` 登记，再同步本表

### 6.4 与组件/协作模式的关系

强需求指定的是**主渠道**（用谁）；组件 S1-S10 与协作模式（怎么配合）照常叠加——例如"小红书珠宝爆款调研"：主渠道指定小红书站内（强需求），叠加 S6 平台双排序+S10 信号词扫描，协作模式用并行扇出+共识（A 查图文、B 查视频、C 查评论再合并）。
